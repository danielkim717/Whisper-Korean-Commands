# 프로젝트 진행 과정

## 목표

짧게 말한 한국어 명령을 구분해 앱의 반응으로 연결하는 것이 목표였습니다. ‘불 켜/불 꺼’, ‘앞으로 가/뒤로 가’처럼 비슷한 명령을 구분하고, 등록하지 않은 말을 잘못된 명령으로 실행하지 않는 문제를 다뤘습니다.

## 음성 전처리와 모델

16 kHz의 3초 음성은 48,000개 샘플입니다. 모델 안에서 STFT·Mel 필터·로그 변환을 거쳐 80×300 특성을 만듭니다. FFT 크기는 400, hop은 160입니다. 기본 구현의 프레임 처리 방식은 공식 Whisper 함수와 완전히 같지 않아 [검증 문서](REPRODUCIBILITY.md)에 차이를 적었습니다.

Whisper small 인코더를 사용하며, 문자 생성 디코더는 사용하지 않습니다. 3초에 맞게 위치 임베딩을 150개로 줄이고, 150×768 출력을 시간축 평균으로 768차원 표현으로 만듭니다. 분류기는 `Linear(768,256) → ReLU → Dropout(0.3) → Linear(256,11)`입니다.

인코더를 고정한 특징 추출이 아니라 전체 인코더와 분류기를 함께 미세조정합니다. CrossEntropyLoss와 Adam, 학습률 1e-5를 사용합니다. 발표의 ‘선형 분류기’는 코드에서 위 두 선형층과 활성함수로 구현되어 있습니다.

## Unknown 거절

일반 분류기는 다른 말이나 소음이 들어와도 11개 중 가장 높은 점수의 명령을 선택합니다. 이를 완화하기 위해 익숙한 명령의 중심과 얼마나 가까운지 확인했습니다.

1. 학습 음성의 임베딩을 길이 1로 정규화한다.
2. 클래스별 평균을 다시 정규화해 중심을 만든다.
3. 입력과 중심의 코사인 거리 `1 - cosine_similarity`를 계산한다.
4. 최소 거리가 임계값보다 크면 -1, 아니면 분류기 명령을 반환한다.

원본 export 기준은 0.125이며 별도 분석 셀은 학습 거리의 p90·p95·p97·p99를 확인합니다. p99는 정답 확률 99%가 아닙니다. 기준을 엄격히 하면 올바른 명령도 거절할 수 있어, 명령어 정확도와 거절률을 함께 살펴야 합니다.

## 모바일 연결

발표에서는 3초 녹음 버튼, 결과·신뢰도 표시, 인식 로그 UI를 시연했습니다. 노트북은 RawAudio 입력을 받는 TorchScript Lite 파일을 내보냅니다. 앱 소스·APK·학습 가중치가 제공되지 않아 저장소에 포함하지 않습니다.

원본 export 로그는 약 1.03 GB이고 trace 입력은 1×48,000으로 고정됩니다. 내보내기 성공만으로 실제 기기에서의 연산 지원·추론 속도·메모리가 검증된 것은 아닙니다.

## 얻은 점

사전학습 표현을 분류 과제로 옮기는 전이학습, 오디오 특성과 모델 입력 크기 정렬, 명령어 분류와 Unknown 거절의 구분, 앱 사용자 흐름으로의 연결을 경험했습니다. 독립 화자·Unknown 평가와 모바일 자원 검증은 후속 과제입니다.
